# Audit: reviewer on Forge (ADR-047)

Reviewed on 2026-10-29 in a fresh context, read-only, against `main...HEAD` plus the working tree
on `feature/forge-reviewer`, and against `docs/design/08-ai-reviewer-specification.md` and
ADR-046/047. `.venv/bin/python -m pytest tests/integration/test_forge_review.py
tests/unit/test_pilot_workflows.py -q` passes. One trivial model call was made to probe the CLI
flags; its reply text was not captured (see M1), so the MCP finding rests on the configuration and
the flag help, not on an observed tool list.

Result: **not ready to merge as is.** No participant-code execution path was found (item 1 below is
clean), but two High findings weaken what the Actions design guaranteed, and the model sandbox is
less closed than the docs and test claim.

## What was checked and found sound

1. **Nothing a participant wrote is executed or imported.** `uv run --project <base>` and `python <base>/tools/ai_review.py` use only the fresh clone of `main`; the participant tree is extracted to a sibling `pr-N/` folder, never `base/`, so it is not on `sys.path`, not a project, and not cwd for any step (`cwd=base`). `fetch_pr_data.sh` extracts through `git archive | tar` with `--no-same-owner --no-same-permissions` then deletes links; I confirmed with GNU tar 1.35 that a symlink followed by a file beneath it fails (`Cannot open: Not a directory`) rather than writing outside. Path traversal is blocked by Git's own path rules and by `push_review`'s resolve and ancestor-link checks. YAML goes through the audited strict loader. Residual: parser or dependency bugs (see H2).
2. **The model process has no GitHub token in its environment** (`call_model_cli` allowlists `PATH HOME LANG USER XDG_CONFIG_HOME`; cwd is an empty temp dir, removed after). The token reaches only `apply`, passed in its environment and, for git, as an `http.extraheader` built from environment config (not argv). Caveat: `HOME` keeps `~/.config/gh/hosts.yml` reachable; see H3.
3. **Apply guards**: `validate_plan`, the head-SHA comparison against the live PR, the fetched-SHA comparison, a shallow clone re-checked against the plan's head, writes confined to `participant/`, no write through links, a non-fast-forward push abandoned, hooks disabled, global/system git config ignored. An unconfigured token escalates. `fcntl.flock(LOCK_NB)` is acquired before the temp dir is made and is released at process exit, and `finally` removes the temp dir on normal and exception exits (not on signals, see M3).
4. **Mode handling**: unset or empty gives `shadow`; an unknown value returns exit 2 before any work; `off` returns 0 before the lock or clone. Mode is read from the environment once and passed identically to review and apply.
5. **`claude --help`** confirms `--tools ""`, `--setting-sources`, `--no-session-persistence`, `--json-schema`, `--strict-mcp-config`, `--disable-slash-commands`, `--restricted`, `--bare` exist; `--bare` needs an API key so it is not usable on the login path.

## Lost from the GitHub Actions design

- A scoped, single-repository bot credential (H2) and a hosted, ephemeral, network-isolated-from-home runner (M3, M4): the model and apply steps now run as the owner's user with the owner's home.
- Salted sampling by default (H1).
- Immediate trigger when the pre-check passes (now up to ten minutes) and a visible run log and summary per decision (now the journal only), and failure visibility in the Actions UI (M2).
- A test that fails if one job holds both secrets (`tests/unit/test_pilot_workflows.py`) has no equivalent for the Forge environment beyond the two names.
- Independence from one machine: if Forge is off, hand-ins wait (documented).

## Re-audit after fixes (2026-10-29)

- **H1 fixed:** `forge_review._salt` uses `PILOT_AI_SAMPLE_SALT`, else makes a random 256-bit salt once
  in the state folder (mode 0600) and reuses it; tested.
- **H2 reduced, residual accepted:** `PILOT_BOT_TOKEN` in the env file (a token scoped to the program
  repository) is used when set; otherwise the machine's `gh` token, with the exit status checked and
  no apply without a token. The broad-token fallback is a documented residual: the apply step parses
  participant files with the repository's own code and executes none.
- **H3 fixed:** `--strict-mcp-config` added (user-scope MCP servers are not loaded); tools, settings
  and session were already off; the process has no GitHub token in its environment; tested.
- **M2 fixed:** a run that could not complete a hand-in pings once per pull request.
- **M3 fixed in part:** a timeout kills the process group; SIGTERM runs cleanup. No file-size cap
  beyond GitHub's own.
- **M4 fixed in part:** `PrivateTmp`; the guide adds `loginctl enable-linger`. Further sandboxing
  would block the `claude` and `gh` logins the runner needs.
- **M5 reduced:** the GitHub review text begins "Automated review by Claude."; the recorded reviewer
  name was already "Claude (automated reviewer)".
- **M1, M6, L1, L3, L4 accepted/noted:** the runner is the one file copied to the server (documented);
  `--repo`/`--ref` are owner-only flags. L2: a manual run blocked by the lock now exits 75.
