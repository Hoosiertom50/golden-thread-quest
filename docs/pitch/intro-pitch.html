The AI Context Engineer Journey

The Golden Thread Quest

From human intent to verified delivery.

Most delivery problems start before code and surface after it. A decision made in a meeting never becomes a clear requirement. A test passes, but nobody can show which requirement it proves. The Golden Thread Quest is a self-paced training program that teaches people to close that gap, using AI agents as working tools and real files as proof.

Conversation → requirement → work item → implementation → test → evidence → outcome

Participants learn the two ends of that thread. The intent end turns stakeholder conversations into structured, traceable work. The validation end checks delivered behavior against that intent and keeps evidence a reviewer can trust.

Who it is for

Participants

Business analysts, manual testers, Scrum facilitators, QA professionals and technical analysts who want practical agentic workflows. No Git knowledge is needed for the pilot.

Reviewers

Mentors, facilitators and program owners who read the evidence and decide whether a quest is verified.

Program owners

People who need to know who has built real skill, and who can add or change curriculum without a developer.

What makes it different

  • Evidence, not checkboxes. A participant hands in repository artifacts, reproducible steps and validator results. A checked box is only a claim.
  • Verified means a person said so. Claimed, locally checked, submitted, needs-changes and verified are separate states. Only a reviewer's approval produces verified completion.
  • Local-first. The application runs on the participant's own machine, bound to localhost. Their work stays in ordinary files in their own Git repository. The application reads and checks it, and does not own it.
  • Safe by design. The application never writes to Jira, GitHub or Trello. In those quests the participant builds the write with a preview, confirmation, duplicate check and sandbox limit, and a reviewer inspects it.
  • Professional tone. It reads like a field guide for a consulting team, not a game.

How a participant works

  1. Pick. The home page recommends the next quest. Quests unlock as their prerequisites are verified.
  2. Build. Read what the quest asks for, then produce real files in your own repository.
  3. Check. The application runs the objective checks locally and shows what passed.
  4. Hand in. One command sends the work to a reviewer.
  5. Get reviewed. The reviewer approves it or asks for changes with reasons. Approval is what earns verified credit.

The Quest Map shows every region and how many of its quests a reviewer has verified.

What a program gets

  • Participants who leave with a body of reviewed work, not a certificate of attendance.
  • Reviewers who see exactly what was required, what was submitted and what the checks found.
  • Curriculum that is plain Markdown and YAML. Add a valid quest file and the catalog, map, filters and search update with no UI code change.
  • Updates from the upstream curriculum that do not overwrite a participant's work.

Where it stands

Pilot release 0.3.1. Not for general use. The engine is built and passed its release checklist on a clean clone, covering the participant, reviewer, maintainer and failure flows in a real browser. All 128 quests are written and have been read by independent audit passes. They have not yet been worked through by a full cohort. The installed Cowork app, the primary target, has not yet been tested. Interfaces and content can change during the pilot, and no upgrade path is promised to the first general release.

Get started

Repository: https://github.com/beekeeper-lab/golden-thread-quest

You need: a Mac or Linux computer (Windows via WSL Ubuntu), a free GitHub account and about ten minutes. No Git or coding skill is required. Use made-up material only, because your work is stored on GitHub.

  1. Open a terminal and paste this one line:
    curl -fsSL https://raw.githubusercontent.com/beekeeper-lab/golden-thread-quest/v0.3.1/install.sh | bash
  2. Answer its prompts. It asks before installing anything and signs you in to GitHub.
  3. The application opens in your browser. Start with Ingest a Meeting Transcript (BA Ruins), then Establish a Safe Local Quest Repository (Base Camp).
  4. Later, run gtq start to reopen it, gtq hand-in to send work for review and gtq get-review to bring the review back.
